# MCP 页面场景化改造复盘

## 项目概述

将元典开放平台 MCP 页面从技术导向改造为法律人友好的场景化页面。
- **启动**：2026-05-12（阿成与小开讨论确认方向）
- **上线**：2026-05-20
- **核心矛盾**：页面信息架构按"开发者接入 MCP 协议"组织，法律人需要的是"我用 AI 能查到什么法律数据、怎么用"

## 改造前的问题诊断

| 问题 | 表现 | 影响 |
|------|------|------|
| 技术黑话直接透出 | Hero 写"3 步跑通 MCP 调用""Streamable HTTP Server" | 法律人看不懂，直接流失 |
| 信息层级倒置 | 服务状态面板排第二，能力目录排后半 | "能帮我干什么"被埋 |
| 没有场景入口 | 三个 Server 按数据分类（法规/案例/企业） | 这是数据维度，不是法律工作维度 |
| 工具表太原始 | 列接口名、MCP Tool、HTTP 方法、积分 | 缺少"这个工具能解决什么法律问题" |
| 配置代码同等暴露 | JSON 配置、Authorization Header 对所有用户展示 | 法律人看到就退缩 |
| 缺少"为什么" | 只讲"怎么接入"，没讲"接入后能做什么" | 缺乏转化动机 |

## 竞品对标：企查查 agent.qcc.com

**行业标杆**，提取 10 个关键设计模式：

1. **分站策略**：MCP（agent.qcc.com）和传统 API（openapi.qcc.com）两个独立站点
2. **用户分岔**：「💼 我是业务用户」「⚙️ 我是技术/开发者」→ 两条完全不同的路径
3. **场景翻译层**：把 179 个工具翻译成 4 个业务场景 + ROI 量化（"人工尽调 2 小时→3 分钟"）
4. **自然语言 UI**：给用户的是"请加载企查查银行客群的 SKILL 集：https://..." 而非 JSON 配置
5. **即时验证**：「复制 Prompt」按钮 + 预期成功结果说明，30 秒验证
6. **技术后置**：JSON 收到登录后/折叠区，CLI 标记"可选"
7. **Server 命名隐喻化**："风控大脑 Server"而非"司法风险数据 Server"
8. **FAQ 来自真实故障**："Claude 里没有调出工具怎么办？"
9. **SKILL 广场**：27 个预装工作流，分 4 个行业（银行/投资/法务/供应链）
10. **登录后 Key 自动替换**：配置区未登录显示占位符，登录后自动替换

## 我们的设计决策

### 核心理念：两层设计
- **外层（给法律人看）**：场景化、去术语、讲"能查什么"→"怎么用 AI 查"
- **内层（给开发者看）**：保留现有技术细节，收进折叠区或二级页

### 5 个场景入口

用法律任务做入口，不用数据分类：

1. **诉讼准备与评估** — 查对方涉诉/执行/财产线索 + 找法条/类案
2. **合同审核与主体核验** — 核验工商状态 + 风险扫描
3. **投资/并购尽调** — 企业全维画像 + 知产盘点 + 司法风险排查
4. **合规审查** — 批量合规排查 + 资质验证
5. **AI 法律文本核验** — 幻觉检测

### 三层命名体系

| 层级 | 面向谁 | 逻辑 | 示例 |
|------|--------|------|------|
| 场景名 | 所有法律人 | 动词+法律任务 | "诉讼准备与评估" |
| 能力名 | 想了解详情的用户 | 动词+能查到什么 | "查对方涉诉历史" |
| 工具名 | 开发者 | `yuandian_` + routeKey | `yuandian_law_vector_search` |

### 信息架构

```
1. Hero：价值主张 + 一句话场景描述
2. 场景入口（核心交互区）：5 个场景卡片
3. 能力目录（按场景分组，不再按数据分类分组）
4. 如何接入（两个标签页/折叠区）：
   - 「我是法律人，只想用」→ Prompt 模板
   - 「我是开发者，要接入」→ JSON + 文档
5. 工具速查表（给开发者的，折叠/二级页）
```

## 关键经验

**Why：** 法律人不是开发者，他们不关心 MCP 协议、Transport、routeKey 是什么。他们关心的是"我的案子能不能用这个查到什么"。

**How to apply：**
- 任何面向法律人的产品页面，先做"场景翻译层"——把技术能力翻译成法律任务
- 用户分岔不是可选项，是必选项：业务用户和开发者需要完全不同的信息架构
- 自然语言 UI 比 JSON 配置转化率高一个数量级
- 即时验证（复制 Prompt + 预期结果）是降低试用门槛的最有效手段

## 待观察
