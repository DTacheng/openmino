# 知行架构原则

> 阿成对整个智能体工作体系的顶层设计。所有工作空间和知识库的组织都遵循这个原则

## 核心：知行分离

智能体架构分为**知**和**行**两个层面：

### 知 — 共享知识层（brain/）

- **全局对齐**：一个脑子，所有工作空间共享同一套知识
- **持续进化**：工作中不断积累、修正、更新
- **求真求准**：知识库是事实和判断的权威来源，不容含糊

知识库不属于任何一个工作空间，它属于「人」——是阿成的工作认知的外化。

### 知识层内部：客观与主观分离

知识层本身进一步区分：

- **客观资料（sources/）**：外部事实——有出处、有链接、可验证、可存档。研究和工作中引用过的所有外部资料都索引在这里。
- **主观知识（concepts/ insights/ decisions/）**：我们基于客观资料做出的总结、提炼、判断、决策。通过 `refs:` 字段引用 sources/，保持可溯源。

**为什么分离**：事实不会因为我们的判断改变而改变。当判断需要修正时，原始资料仍在，可以重新审视。混在一起就分不清"数据说的"和"我们觉得的"。

### 行 — 任务工作空间

- **目标驱动**：每个工作空间围绕一个明确的任务目标搭建
- **交付定义边界**：工作空间的边界由「直接相关的文件和产出」来界定，不是主题、不是部门、不是时间
- **各自独立**：工作空间之间不直接耦合，它们通过知识层间接关联

## 实践含义

| 场景       | 知（brain/）                   | 行（工作空间）        |
| -------- | --------------------------- | -------------- |
| 产品数据更新了  | 更新 brain/concepts/法律元力产品.md | 不需要同步改培训材料     |
| 准备新演讲    | 从 brain/ 读取最新数据和洞见          | 在培训空间产出逐字稿和PPT |
| 培训中发现新洞见 | 写回 brain/insights/          | 培训空间只管交付物      |
| 做产品决策    | 记录到 brain/decisions/        | 法律元力空间执行决策     |

**信息流向**：行 → 知（工作产生知识）→ 行（知识指导下一次工作）

## 判断标准

- 一条信息应该放 brain/ 还是工作空间？问自己：**这条信息在别的工作空间也有用吗？**
  - 有用 → brain/
  - 只服务于当前交付物 → 留在工作空间
